### 搜索语法
这里以我常用的**Bing**作为主要学习的搜索引擎。
#### 1. 核心操作符
| 操作符 | 作用 | 示例 | 备注 |
|---|---|---|---|
| `" "` | 精确匹配短语 | `"人工智能发展报告"` | 结果过少时可能被忽略 |
| `-` | 排除关键词 | `苹果 -手机 -iPhone` | 可叠加使用 |
| `site:` | 限定网站/域名 | `site:gov.cn 高考` | 冒号后不加空格 |
| `filetype:` | 限定文件类型 | `filetype:pdf 年度报告` | 支持 pdf、docx、ppt 等 |
| `intitle:` | 关键词出现在标题 | `intitle:"后台登录"` | 可配合引号精确匹配 |
| `OR` / `\|` | 满足任一条件 | `(ChatGPT OR 文心一言) 对比` | `OR` 必须大写 |

---

#### 2. Bing 独有 / 进阶操作符

| 操作符 | 作用 | 示例 | 备注 |
|---|---|---|---|
| `contains:` | 查找链接到指定文件类型的页面 | `site:example.com contains:pdf` | 找的是“链接页”，不是文件本身 |
| `linkfromdomain:` | 查某域名的所有出站链接 | `linkfromdomain:example.com` | 适合分析外链 |
| `feed:` | 搜索 RSS/Atom 订阅源内容 | `feed:科技新闻` |  |
| `hasfeed:` | 查找带订阅源的页面 | `site:example.com hasfeed:` |  |

* Proxy：代理拦截，抓取、查看、修改浏览器和服务器之间的 HTTP/HTTPS 请求。
* HTTP history：HTTP 历史记录，查看经过 Proxy 的所有请求和响应。
* Repeater：重放器，手动修改单个请求并反复发送，观察响应变化。
* Intruder：入侵者/自动化攻击模块，用于爆破、枚举、参数 Fuzz、目录扫描等。

|  | GET | POST |
|---|---|---|
| 主要作用 | 获取资源、查询 | 提交数据、创建/修改 |
| 参数位置 | URL 查询字符串 `?a=1&b=2` | 通常在请求体 body |
| 可见性 | 地址栏、历史、日志可见 | 相对不显示，但抓包可见 |
| 缓存/书签 | 可缓存、可书签 | 通常不缓存、不可书签 |
| 限制 | 受浏览器/服务器限制 | 一般可传更大数据 |
| 典型场景 | 搜索、分页、查详情 | 登录、注册、发帖、上传 |

#### HTTP 状态码速查表

| 状态码 | 含义 | 抓包时看什么 |
|---|---|---|
| 200 | OK 成功 | 正常响应 |
| 201 | Created 已创建 | POST 创建成功 |
| 204 | No Content | 成功但无 body |
| 301 | 永久重定向 | Location 新地址 |
| 302 | 临时重定向 | 登录跳转最常见 |
| 304 | Not Modified | 缓存有效 |
| 400 | Bad Request | 参数错误 |
| 401 | Unauthorized | 未认证，常带 WWW-Authenticate |
| 403 | Forbidden | 已认证但无权限 |
| 404 | Not Found | 资源不存在 |
| 405 | Method Not Allowed | 方法不对 |
| 429 | Too Many Requests | 限流 |
| 500 | Internal Server Error | 服务端异常 |
| 502 | Bad Gateway | 网关/上游错误 |
| 503 | Service Unavailable | 服务不可用 |
| 504 | Gateway Timeout | 网关超时 |

```python
from flask import Flask, request, render_template
#从 flask 包导入 Flask 类、request 对象、render_template 函数。
#Flask：创建 Flask 应用。
#request：获取请求信息，比如表单数据、请求方法。
#render_template：渲染 HTML 模板文件。
#创建一个 Flask 应用实例
app = Flask(__name__)
# 用字典模拟一个简单的用户数据库
users = {
    "admin": "admin123",
    "user": "user123"
}
@app.route('/', methods=['GET', 'POST'])
#路由装饰器，把下面的 login() 函数绑定到网站根路径。同时支持GET和POST请求。
def login():
#定义视图函数，当访问 / 时执行。
    if request.method == 'POST':  
        # 如果是 POST 请求，说明用户提交了表单
        username = request.form['username']  
        # 获取表单中的用户名
        password = request.form['password']  
        # 获取表单中的密码
        if username in users and users[username] == password:  
            # 检查用户名和密码是否正确
            return f"欢迎, {username}!"  
            # 登录成功，返回欢迎信息
        else:
            return "用户名或密码错误，请重试。"  
            # 登录失败，返回错误信息
    else:  
        # 如果是 GET 请求，说明用户只是访问页面
        return render_template('login.html')  
        # 渲染 login.html 模板并返回
if __name__ == '__main__':
     app.run(debug=True)
```

### SQL Injection漏洞学习
总算是到正题了，当前北京时间26年9月28号00:25,累死了喵，~~突然想rua小肥龙尾巴了。~~

#### 1、产生原因
应用程序没有把“用户输入的数据”和“SQL 代码”正确分离，导致用户可控输入被数据库当作 SQL 语句的一部分执行了。也就是说SQL 注入不是数据库本身“自动产生”的漏洞，而是应用层动态构造 SQL 时，把数据错误地当成了代码。
以下为deepseek提供的示例：
```text
' OR '1'='1 #用户的输入
```
经过魔法拼接变成如下格式：
```sql
SELECT * FROM users 
WHERE username = '' OR '1'='1' AND password = ''

```
原本是查用户名和密码，结果条件被改成恒成立，从而绕过验证。
#### 2、危害
前面已经说了，可以绕过验证，那么很显然，可以用这个方式提权，然后。。。。嗯，数据库账号权限越高，他能干的事越多。（如果是root呢？乐，洗洗睡吧，救不回来了）
#### 3、寻找
找到用户可控的输入点，判断它是否进入 SQL 查询，再验证输入能否改变 SQL 的语义或执行结果。
所有能进入后端的输入都值得尝试，所以要找全，如：GET/POST，Cookie等。
之后使用可以破坏sql语法的字符，如单引号，双引号，反斜杠，括号等。
或者直接查看源码关注字符串拼接和动态SQL。
